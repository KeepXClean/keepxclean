# 弹窗与 X 侧栏样式修复

2026-11-11，根据实际使用截图修复两处布局问题。

## 原因与修复

1. 工具栏弹窗使用 `width: min(400px, 100vw)`，其内容尺寸受浏览器初始窄视口限制。此前验收宿主额外设置 `body.width = 400px`，没有覆盖生产文档的初始尺寸约束。现在生产 popup HTML 使用独立文档类和 stylesheet 为 html / body / root 提供 400px 宽度与最小宽度；组件本身宽 400px，头部和底部不参与纵向压缩。验收宿主删除独立宽度补偿，改用同一生产样式。
2. “净空设置”入口沿用扩展通用 14px 字号，并覆盖为白色描边胶囊，与 X 20px 导航不一致。现在移除描边与常驻背景，读取原生导航文字、图标的实际字号、字重、颜色、行高和间距。原生侧栏收起时只显示图标，保留可访问名称。尺寸、主题、字体变化及导航替换后重新同步；观察器随页面卸载清理。设置抽屉继续使用浅色背景。

## 本次验证

- extension 30 项测试通过；extension 类型检查通过。
- `pnpm --filter @keepxclean/extension zip` 完成生产构建与打包。
- Ego 本地样本：初始 iframe 视口 200px 时，生产文档、body、popup 及内容固有宽度均为 400px；按内容宽度展开后，三档预设单行显示，底部边界恰为 600px。
- 侧栏样本：扩展与原生入口均为 20px 字号、50px 高度；无描边；深色主题下文字颜色跟随原生，打开的设置抽屉仍为白色。
- 900px 视口收起后入口为 50px 图标按钮；不刷新扩展到 1440px 时文字恢复。原生文字调整到 22px 后入口同步更新。
- 本次仍使用 Ego 样本宿主验证，未自动加载浏览器真实工具栏弹窗；用户提供的实际截图是本次问题证据，不将样本检查描述为真实扩展环境验收。
